## Какие риски проверялись

- Две правки одной версии задачи: один успех и один 409, без второго изменения истории.
- Два перемещения к одному якорю: наблюдалось реальное ожидание блокировки PostgreSQL;
  обе задачи сохраняются в согласованном порядке.
- Чужие проекты и вложенные ресурсы: отказ без раскрытия содержимого.
- Удаление участника и выход: последующие запросы теряют доступ; открытые сокеты закрываются.
- Серверный аудит: приложение не может UPDATE/DELETE/TRUNCATE; soft delete сохраняет историю.
- Миграции: runtime-роль не может менять Alembic version и схему.
- PATCH: пропуск и null различаются, неверные ссылки откатываются, no-op не создает историю.
- Аналитика: первые завершения, повторное открытие, мягкое удаление, часовые пояса и нули.
- Пакетное чтение: количество SQL-запросов не растет отдельно на каждую карточку.
- Seed: повторный запуск не перезаписывает существующих пользователей и учебную историю.

## Найденные и устраненные дефекты

1. Пустой HTTP POST мог приходить двумя ASGI-кадрами; первый пустой кадр с `more_body=True`
   ошибочно считался телом и приводил к 415 при logout. Обработчик теперь пропускает
   пустые промежуточные кадры и проверяет Content-Type только при реальных байтах тела.
   Добавлены проверки как пустого logout, так и non-JSON после пустого кадра.
2. Общие default privileges давали runtime больше прав на служебные таблицы, чем нужно.
   Миграция 0003 оставляет SELECT на Alembic и SELECT/INSERT на аудит.
3. Недоступность БД и timeout блокировки могли попадать в общий 500. Теперь известные
   временные SQLSTATE возвращают безопасный 503 без строки подключения или SQL-параметров.
4. Ошибка уведомления сокета после удаления участника могла испортить успешный HTTP-ответ.
   После commit ошибка доставки не отменяет факт сохранения и не превращает его в ложный отказ.
5. Учебный домен `example.test` не принимался стандартной настройкой email-валидатора.
   Синтаксис по-прежнему проверяется, зарезервированный учебный домен разрешен явно.

Старые foundation-тесты также приведены к общему Origin-правилу и раздельным учетным данным
миграций/runtime. Защита приложения не ослаблялась ради ожидаемого кода ответа в старом тесте.

FastAPI 0.141.1, SQLAlchemy 2.0.52, Alembic 1.19.2, asyncpg 0.31.0,

Для активации компонентов Windows требуется перезагрузка; автоматическая перезагрузка
не выполнялась. PostgreSQL работает независимо от этой перезагрузки.
