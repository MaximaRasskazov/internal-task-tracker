# Подключение Vue к готовому API

## Начальная точка

Сначала запустить миграции и seed по README. Проверить `/api/v1/health/ready` и открыть `/docs`.
Основной машинный контракт — `docs/api/openapi.json`; копировать DTO вручную из отдельных
ответов не требуется. Генерацию TypeScript-типов и проверку их актуальности добавить
в frontend-коммит вместе с первыми клиентскими API-функциями.

Для Vite настроить proxy `/api` и `/ws` к FastAPI; для `/ws` включить WebSocket.
В разработке origin страницы `http://localhost:5173` уже разрешен локальным окружением.
Cookie отправляется с запросами. JWT никогда не сохраняется в localStorage.

## Очередность экранов

1. Вход, восстановление сессии через `/auth/me`, выход.
2. Список проектов и проект с участниками.
3. Доска из одного `BoardSnapshot` и форма создания задачи.
4. Карточка задачи, комментарии и история.
5. Перемещение, конфликт версий и серверные фильтры.
6. WebSocket, восстановление соединения и аналитика.

Так каждый следующий экран опирается на уже проверенный путь получения сессии и проекта.
Проверку реального HTTP не откладывать до готовности всех макетов.

## Сессия и ошибки

Login возвращает `{user, csrf_token, expires_at}` и HttpOnly cookie.
CSRF-токен хранится в памяти приложения. После перезагрузки `/auth/me` возвращает его снова.
Все изменяющие запросы передают `X-CSRF-Token`; запросы с телом используют JSON.

| Ответ | Поведение интерфейса |
|---|---|
| 401 | Очистить сессию, закрыть сокеты, открыть вход с адресом возврата |
| 403 | Показать понятный отказ; при отзыве доступа перечитать проект |
| 404 | Сообщить, что ресурс недоступен, без раскрытия чужого проекта |
| 409 VERSION_CONFLICT | Сохранить введенный текст отдельно, перечитать актуальное состояние |
| 409 POSITION_CONFLICT | Перечитать полный порядок и предложить повторить перемещение |
| 422 | Показать ошибки `error.details` у соответствующих полей |
| 429 | Выдержать Retry-After перед новым входом |
| 503 / сеть | Показать повтор чтения; не повторять автоматически неизвестный write |

## Поля и формы

Имена транспорта — `snake_case`. Deadline — календарная дата, не timestamp;
не пропускать ее через преобразование UTC, которое может сдвинуть день.
Пропущенное поле PATCH сохраняет значение. `null` допустим только для assignee, deadline
и story_points. Набор `tag_ids` заменяется целиком. Серверные author_id, number и
position не отправляются из формы.

## Доска и перемещение

`GET /boards/{id}` возвращает board, project, revision, server_time, columns, tasks,
members и tags из согласованного чтения. Колонка имеет произвольное имя и неизменную
category: todo / in_progress / done. Завершенность вычисляется по category.

При перемещении отправляются `column_id`, `before_task_id` и `expected_version`.
Якорь — ID карточки, перед которой выполняется вставка, а `null` означает конец колонки.
Индекс видимого массива не передается. Это сохраняет правильный порядок даже при скрытых
фильтром карточках. Для одной карточки одновременно допускается одна неподтвержденная операция.

HTTP-ответ содержит `board_revision`. Старый ответ или снимок не должен заменять более
новое состояние. Техническое перемещение соседей может изменить position без их version,
поэтому сравнения только task.version недостаточно для порядка всей доски.

## Фильтры

Разные виды условий объединяются AND. Все выбранные теги обязательны; приоритеты и колонки
объединяются OR внутри своего вида. Использовать повторяемые query-параметры для списков,
например `tag_ids=id1&tag_ids=id2`. `assignee_id=unassigned` выбирает неназначенные задачи.
Фильтры хранятся в URL страницы, чтобы refresh и общая ссылка давали ту же выборку.

## WebSocket

Подключение: `/ws/v1/boards/{board_id}`, авторизация через ту же cookie и Origin.
После `connection.ready` запросить HTTP-снимок. Для каждого события запоминать максимальную
увиденную revision; если снимок отстает, перечитать его. Применять только более свежие снимки.

Heartbeat приходит раз в 15 секунд. После 35 секунд без сообщений соединение считается
потерянным. После восстановления повторяется ready → снимок → сверка revision.
События дедуплицируются по event_id; сокет не принимает бизнес-команды.

Коды 4401, 4403 и 4404 означают потерю сессии, доступа или удаление доски соответственно;
после них бесконечный reconnect не запускается. При offline сохраняются видимый снимок
и введенный текст, а новые изменения блокируются.

## Что показать на проверке frontend

Нужны реальные Network-запросы, две независимые сессии, создание/изменение/перенос задачи,
конфликт версии, потеря и возврат соединения, удаление участника с открытой доской,
фильтр минимум по трем видам условий и оба графика. Скриншоты делать без cookie,
паролей и содержимого локального `.env`.
